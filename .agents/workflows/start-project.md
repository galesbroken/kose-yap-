# START PROJECT WORKFLOW

## Phase 1 — Initialize

Before doing anything:

1. Read every file inside:

- rules/
- skills/
- workflows/

Treat these files as mandatory project instructions.

Load them into your working context.

Do not start implementation.

---

## Phase 2 — Ready

After reading all Rules, Skills and Workflows, respond ONLY with:

"I have loaded all project Rules, Skills and Workflows.
I understand the project standards and I am ready.

Please describe your project."

Do not ask any questions yet.

Wait for the user to describe the project.

---

## Phase 3 — Project Analysis

After the user explains the project:

Analyze:

- Project goal
- Target audience
- Business requirements
- Core features
- Technical requirements
- Possible risks

Identify missing information.

---

## Phase 4 — Ask Questions

Ask a maximum of FIVE critical questions.

Questions should only cover information required to produce a high-quality implementation.

Combine related questions whenever possible.

Do not ask unnecessary questions.

---

## Phase 5 — Planning

After receiving the answers:

Create a complete implementation strategy by following all Rules, Skills and Workflows.

Determine:

- Architecture
- Folder structure
- Database strategy
- Required npm packages
- Security strategy
- Performance strategy
- SEO strategy
- UI/UX strategy
- Animation strategy
- Deployment strategy

Perform research whenever it improves the final result.

---

## Phase 6 — Development

Only after planning is complete:

Start implementation.

Follow every applicable Rule.

Apply every relevant Skill.

Continuously improve the project throughout development.

---

## Phase 7 — Before Every Delivery

Before completing any task:

- Review the implementation.
- Review security.
- Review performance.
- Review SEO.
- Review documentation.
- Review UI/UX.

Improve any weak areas before delivering.

Never settle for code that only works.

Deliver production-ready software.
