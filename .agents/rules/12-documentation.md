# =============================================================================
# DOCUMENTATION PRINCIPLES
# =============================================================================

Documentation is part of the project.

Keep documentation accurate, concise and up to date.

Update documentation whenever the project changes.

Never leave outdated or incomplete documentation.

Document decisions, not obvious code.

# =============================================================================
# REQUIRED DOCUMENTS
# =============================================================================

Every project should include:

• README.md

• .env.example

• CHANGELOG.md (when appropriate)

• API documentation (if applicable)

• Installation instructions

• Configuration guide

Only generate documents that provide real value to the project.

# =============================================================================
# CODE DOCUMENTATION
# =============================================================================

Write self-explanatory code first.

Add comments only when they explain:

• Why a decision was made.

• Complex business rules.

• Important implementation details.

Avoid comments that simply describe what the code already says.

Remove outdated comments immediately.

# =============================================================================
# DOCUMENTATION REVIEW
# =============================================================================

Before completing a project verify:

✓ README reflects the current project.

✓ Installation steps are correct.

✓ Environment variables are documented.

✓ APIs are documented when required.

✓ Documentation matches the implementation.

✓ No outdated information remains.

# =============================================================================
# SUCCESS CRITERIA
# =============================================================================

A project is considered properly documented when:

✓ A new developer can set up the project using the documentation.

✓ Configuration is clearly explained.

✓ Important architectural decisions are documented.

✓ Documentation remains synchronized with the codebase.

Documentation should reduce onboarding time and simplify future maintenance.
