# DOCUMENTATION SKILL

## Purpose

Create clear, accurate and maintainable documentation that enables developers to understand, configure and maintain the project efficiently.

---

## Documentation Mindset

Documentation is part of the project.

Write documentation continuously during development.

Never postpone documentation until the project is finished.

Keep documentation synchronized with the implementation.

---

## README

Every project should include a professional README.

Include:

- Project overview
- Features
- Technologies
- Installation
- Configuration
- Environment variables
- Folder structure
- Deployment notes

Keep README concise and practical.

---

## API Documentation

When APIs exist, document:

- Endpoints
- Methods
- Parameters
- Request examples
- Response examples
- Error responses
- Authentication requirements

Documentation should allow another developer to use the API without reading the source code.

---

## Environment

Document every required environment variable.

Provide:

- Variable name
- Purpose
- Example value

Always maintain a `.env.example`.

Never expose secrets.

---

## Code Documentation

Prefer self-explanatory code.

Write comments only when explaining:

- Complex business logic
- Architectural decisions
- Important implementation details

Avoid obvious comments.

Remove outdated comments immediately.

---

## Change Tracking

When appropriate maintain:

- CHANGELOG
- Migration history
- Major architectural changes

Document breaking changes clearly.

---

## Maintenance

Whenever the project changes:

Review:

- README
- API documentation
- Configuration
- Installation steps
- Environment variables

Documentation should never become outdated.

---

## Armes Recommendations

Every production project should provide enough documentation for another developer to:

- Install the project
- Configure the environment
- Start development
- Deploy the application
- Maintain the project

Documentation should reduce onboarding time.

---

## Checklist

✓ README updated

✓ Installation verified

✓ Environment documented

✓ API documented (if applicable)

✓ Comments reviewed

✓ Breaking changes documented

✓ Documentation matches implementation

✓ Ready for handover
